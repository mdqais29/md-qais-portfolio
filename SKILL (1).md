# Portfolio Build Rules — Mohammed Qaisuddin

## 1. Design Rules
- Treat the attached full-page portfolio image as the primary visual reference. Follow its overall composition and section order, but make the final UI polished, spacious, and responsive—not cramped.
- Visual direction: light off-white background, black/dark text, vivid violet accents, clean modern typography, subtle borders, and carefully controlled shadows.
- Hero: keep the portrait as the **central visual anchor of the hero composition**—visually centered, not pushed too far to the right. Balance the headline, short introduction, expertise labels, and CTAs around it.
- Preserve generous whitespace, readable line lengths, consistent alignment, and clear hierarchy. Avoid dense sections, generic template layouts, unnecessary cards, excessive rounded corners, and AI-slop effects.
- Use tasteful parallax and smooth reveal/hover transitions for selected visuals, cards, and sections. Motion must be subtle, performant, accessible, and disabled/reduced when `prefers-reduced-motion` is enabled.
- Mobile, tablet, laptop, and wide desktop are all first-class targets. Recompose layouts for each size; never just shrink desktop. Prevent horizontal overflow and keep text and touch targets usable.
- Do **not** add an intro screen, loading screen, or typewriter welcome sequence. Visitors should land directly on the main portfolio.

## 2. Important Project Rules
- This is a **fresh project in a new folder**. Do not reuse or refer to the old portfolio implementation. Inspect this project's setup before choosing or changing the stack.
- Build in stages: first the page structure and hero; then content and project imagery; then motion/responsive refinement; finally accessibility, SEO, and production checks. Do not implement everything in one rushed pass.
- Keep components reusable and content easy to update. Use the real profile photo and genuine project screenshots where available. Do not use AI-generated mock screenshots to represent real projects.
- Never invent clients, results, metrics, testimonials, skills, credentials, project features, or contact details. If a detail is unconfirmed, omit it or ask.
- Preserve working links and test every CTA, navigation item, accordion, and interactive element. Run the production build and fix errors before finishing.
